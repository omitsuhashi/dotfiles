# Domain Docs

## 調査前に読む文書

single-context 構成を使用する。

- ルートの `CONTEXT.md`: 用語とドメインの定義。
- `docs/adr/`: 調査対象に関係する設計判断。

存在しない文書は読み飛ばして調査を続ける。
文書は domain-modeling により、用語や設計判断が確定した時点で作成する。

## 用語と設計判断

Issue、提案、テストなどでは `CONTEXT.md` の用語を使用する。
必要な概念が未定義なら、既存の用語で表現できるか確認し、
実際の不足は domain-modeling の対象として記録する。

既存 ADR と異なる提案をする場合は、対象 ADR と再検討する理由を明示する。
